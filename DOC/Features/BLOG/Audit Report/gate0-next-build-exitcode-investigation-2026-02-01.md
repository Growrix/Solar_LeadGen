# Gate0: Next build — Exit Code Investigation (2026-02-01)

## Summary
VS Code task **Gate0: Next build** intermittently failed with exit code **1** even though running `npm run build` manually could succeed.

This was not a “random task runner” failure: the task output showed a real Next.js typecheck failure caused by a **stale / inconsistent `.next/types` state**.

## Evidence (captured)
- Failing task output (Gate0: Next build):
  - `Type error: File 'C:/projects/solarmatch/.next/types/app/(dashboard)/dev/written-quote/page.ts' not found.`
  - `The file is in the program because: Root file specified for compilation`
  - `Next.js build worker exited with code: 1`

  Note: the full original failing terminal transcript was not preserved at the moment of failure (the VS Code task output capture truncates in the UI/tooling). The key error lines above are the root-cause signal.

- Manual build immediately after:
  - Running `npm run build` succeeded.

- Full successful transcripts (2026-02-01):
  - Gate0 task command equivalent output: `DOC/Features/BLOG/Audit Report/gate0-next-build-task-output-2026-02-01.txt`
  - Manual `npm run build` output: `DOC/Features/BLOG/Audit Report/manual-npm-run-build-output-2026-02-01.txt`

## Interpretation
`.next/types/**` is generated by Next during build/typecheck. If the folder contains **stale references** (e.g., it expects a generated file that is missing), Next’s internal typecheck step can fail.

A clean rebuild of `.next/types` removes the stale references and allows the build to proceed.

## Fix Strategy
- Modify the VS Code task **Gate0: Next build** to **delete `.next/types` before running `npm run build`**.
- This is a local developer task fix only; CI still runs `npm run build` normally.

Implemented in `.vscode/tasks.json`:
- `powershell -NoProfile -Command "if (Test-Path .next\\types) { Remove-Item -Recurse -Force .next\\types }; npm run build"`

- Gate0: Next build exits **0** when build succeeds.
- Gate0: Next build exits **non-zero** only on real build failures.
