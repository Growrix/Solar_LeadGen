## 0) Non-negotiable content safety rules

- RSS content is used for: topic discovery, source linking, fact-check cues.
- RSS content is NOT used for: copying full text verbatim into our blog posts.
- Generated blog posts must be original writing.

---

## 1) Automation Goals (from your initial plan)

- Auto-generate SEO blog drafts (daily/weekly)
- Minimal admin work (approve/reject/schedule)
- Optional: pull RSS from reputable sources (gov + industry) to discover what to write about
- Scale the pipeline safely (dedupe, retries, job logs, approvals)

---

## 2) Recommended Architecture

### Option A (Simplest): n8n-only orchestration
n8n workflows do everything:
- Cron trigger
- Fetch RSS feeds
- Dedupe
- Call AI (via your chosen provider)
- Create Strapi draft via API
- Notify admin (optional)

Pros: fast, minimal code
Cons: job history/audit trails can be harder to centralize unless you store them explicitly

### Option B (Scalable): n8n + dedicated Automation Worker
- n8n triggers jobs and handles scheduling
- Worker service handles:
  - RSS normalization
  - dedupe logic
  - AI prompt templating
  - quality checks
  - Strapi draft creation
  - persistent job logs

Pros: best scaling + strong auditability
Cons: more engineering

## 3) Core Workflows

### 3.1 Workflow: “Generate Draft from Topic” (Admin-assisted)
Trigger:
- Admin requests “Generate” (either inside Strapi via custom endpoint, or via our app’s admin page calling the worker)

Steps:
1) Accept topic + target keyword + audience
2) (Optional) Pull RSS items relevant to topic
3) Generate:
   - outline
   - draft
   - SEO title/description
   - FAQ
   - suggested featured image prompt
4) Run quality checks:
   - basic duplication checks (internal)
   - readability check
   - forbidden wording checks (if any role-based rules apply)
5) Create draft in Strapi (Draft)
6) Mark job as “Awaiting Approval”

### 3.2 Workflow: “Auto-generate Drafts on Schedule” (Hands-off)
Trigger:
- n8n cron (e.g., daily)

Steps:
1) Choose topics:
   - from a curated topic list OR
   - from RSS trend signals OR
   - from an AI-generated topic backlog (with human approvals)
2) Generate 1..N drafts
3) Create drafts in Strapi
4) Optional: auto-assign category/tag

### 3.3 Workflow: “Scheduled Publishing”
Two approaches:
- Use Strapi scheduling capability if available in your setup
- Or do it via n8n/worker:
  - At publish time, call Strapi to publish the draft

After publish:
- Trigger Next.js revalidation (if using caching)
- Regenerate sitemap (if sitemap is generated by Next.js)

---

## 4) Scaling Strategy

Scaling controls:
- Dedupe keys: (source link + title + publish date) for RSS items; (topic + week) for generated drafts
- Concurrency limits in n8n (avoid API spikes)
- Retry strategy with backoff for:
  - AI calls
  - Strapi calls
- Observability:
  - job status (QUEUED → RUNNING → DRAFT_CREATED → APPROVED/PUBLISHED)
  - error logs stored centrally (worker DB or Strapi “GenerationJob” type)

---

## 5) Approval Strategy (Minimal admin effort)

Default (recommended):
- AI generates drafts → Admin approves/rejects in Strapi

Optional (later):
- Auto-publish only if:
  - content passes quality checks
  - content passes compliance checks
  - topic is from a “pre-approved topic list”

---

## 6) What we will NOT do in Blog Feature scope

- Real-time “News System” ingestion and republishing (separate module later)
- Newsletter digest sending (separate module later)

We only keep “RSS research signals” as optional inputs for Blog topic discovery.
